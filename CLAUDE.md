# Dead Blocks — project notes for Claude Code

A first-person 3D voxel **zombie survival craft** game. The design blends three games:
- **Minecraft**: a block world you can mine and build in, plus crafting.
- **7 Days to Die**: zombies smash through blocks, with a Blood Moon horde every 7th night.
- **ARK**: wildlife to hunt now, with taming and creatures planned.

The owner (Marcus) playtests on Windows and gives feedback. Each round of work should end with a new Windows build he can run.

## Tech
- **Godot 4.7.2 (standard build, not .NET)**, using the **Forward+** renderer (OpenGL fallback; since the graphics overhaul, `docs/V-plan.md`) and **Jolt Physics**. The game runs physics at 60 ticks/s; server mode runs it at 30 (decided in M0, see DESIGN.md).
- Everything is GDScript plus three shaders in `shaders/` (sky, smooth terrain, blocks). There are **no asset files** yet: block textures, the terrain's texture arrays, item icons and crack overlays are painted in code (`tex.gd`), and every sound is synthesized at startup (`sfx.gd`). Downloaded CC0 packs (V3/V4) must stay out of the dedicated-server export.
- `main.tscn` is the only scene. `game.gd` builds every other node in code.
- Indent with tabs and use typed GDScript where possible.

## File map (`scripts/`)
| File | What it does |
|---|---|
| `g.gd` | Autoload `G`. Global refs (game, world, player, hud, sim, tex, sfx), command-line args (plus `server.cfg` on a server, `_load_server_cfg`), `VERSION`, and `server_mode` (`--server-mode`, `--server`, or the dedicated-server export): no render meshes, lights, mob models or sounds, physics at 30 ticks/s. `mode` is solo (the title screen's own world, and the tests that run in-process) / client / server. Holds the client connection (`G.net`, survives the scene reload into the server's world), `host_game` and `play_solo` (both start a background server process and join it; Play solo binds it to 127.0.0.1 with a random port and password, `--solo`; `G.solo` is then true), `world_info` for the title screen, and `start/end_client_session` |
| `game.gd` | Game states (loading/title/playing/menu/chat/paused/dead, plus connecting and server), day-night clock (the look is `gfx.gd`), Blood Moon, zombie and animal spawning (on the server), input bindings. In solo, Esc sends a pause to the server (`clock_stopped` follows the server's clock). Server mode: `_ready_server` (world + Sim + NetServer, no player/HUD). Client mode: seed, clock and position come from the server's welcome; keeps a RemotePlayer per other player and a mob view per mob (`_sync_mob_views`). Server: `_server_spawner` around every online player (max 120 zombies), `set_mobs_paused` while nobody is online, `spawn_near` for `/spawn` |
| `gfx.gd` | `G.gfx` (not on a server): WorldEnvironment, sun/moon light, sky shader, fog and post effects, the day–night look (`update_sky`), the graphics quality (Low/Medium/High/Ultra: AA, shadows, SSAO/SSIL, volumetric fog, view distance 5–8; `--gfx=N` overrides) and `user://settings.cfg` (quality, mouse sensitivity) |
| `smooth_mesher.gd` | `class_name SmoothMesher`: the rounded natural ground (surface nets over the chunk and 4 blocks of its 8 neighbours; corners cut ≤ 0.45, hollows filled ≤ 0.2, smoothed twice), material weights and sky light per vertex (`sky_at` for cube faces too). **Picture only**: collision stays whole blocks on client and server |
| `round_box.gd` | `class_name RoundBox`: rounded box meshes for mob and player models (cached by size) |
| `world.gd` | Chunked voxel world (16×64×16 chunks). Keeps chunks loaded around one or more centers (`update_centers`, one per player). Terrain generation and meshing run on WorkerThreadPool. A drawn chunk is meshed once all 8 neighbours have data (SmoothMesher), as two surfaces (smooth ground, then cubes/boxes/plants); its collision is `_build_collision` (whole blocks, as on the server, which still needs only the 4 side neighbours); an edit within 4 blocks of a border remeshes the neighbours. Also holds raycasts, set_block, zombie block damage with crack overlays, the torch/campfire lights, the box-shaped blocks (`SH_BOX`, `MeshBuf.box`) and the beacon beam over each backpack. Server: `record_edits` collects every block change for NetServer. Client online (`remote`): only chunks the server subscribed as fresh are generated; edited ones arrive as copies (`net_subscribe/net_chunk/net_edits`) |
| `world_gen.gd` | Deterministic terrain: hills, plains/forest/desert biomes, caves, coal/iron ore, trees, berry bushes |
| `blocks.gd` | Block ids and per-block tables (atlas tiles, shape, solid, opaque, hardness, tool, required pick tier, zombie HP; `BOX` sizes for box-shaped blocks). **Block id = item id**. `BACKPACK` is a block that never goes into an inventory |
| `items.gd` | Non-block items (ids ≥ 100): tools, weapons, food |
| `inventory.gd` | 36-slot inventory. Slots 0–8 are the hotbar |
| `rules.gd` | `class_name Rules`: break time and drops, shared by solo play and the server so they always agree |
| `crafting.gd` | Recipe list. Each recipe needs an optional station (workbench/forge/campfire) within 4 blocks |
| `player.gd` | Movement (steps up 1-block ledges by itself, `_step_up`, with the camera easing up), mining, placing, combat, stamina, held item, flashlight. `break_block` / `try_place` / `consume` / `attack` send requests and show the result at once; the server's answer replaces the guess (every game, Play solo included, is on a server since M1.7). Health and food come from the server (`apply_stats`, `hurt_effect`); falls are reported |
| `mob.gd` | Base creature: box models with rounded edges (`RoundBox`), walking, hopping ledges (`tall`: the cells of height the body needs), knockback, hit flash. Online: `net_id`, `net_kind/net_flags` for S_MOBS, and `view` mode (client pictures moved by `view_update`) |
| `zombie.gd` | A zombie's mood (`kind`: day/night/horde) and, since M3, its `type` (walker, runner, brute, crawler, screamer, spitter; numbers in `STATS`, models in `_build_model`). Ticked by the Sim (`sim_tick`), not by `_physics_process`. Goes for the nearest player in its region once it notices them (`notice_range`, keeps `hunting` up to `chase_range`; the horde hunts everyone; `become_day` at dawn), smashes blocking cells (queued through the Sim), takes damage from wood spikes. Screamers call zombies and Spitters spit acid through the Sim's queues (`queue_call`, `queue_spit`) |
| `acid.gd` | A Spitter's acid glob: moved by the Sim in an arc (`step`), hurts the player it reaches or queues block damage where it lands; clients see it as `Proto.MOB_ACID` |
| `animal.gd` | Boar: wanders, flees from the last hit, drops raw meat to whoever killed it |
| `hud.gd` | HUD (with markers for your own backpacks), inventory/crafting screen, title menu (Play solo / Host / Join panels, with "your world continues" and "Start a new world" for solo and host; Join remembered in `user://client.cfg` as hashes only), pause (player list and ping online), death screen, chat box and chat log |
| `tex.gd` | Procedural 16×16 texture atlas and item icons; `terrain_albedo/terrain_normal` (Texture2DArrays, 256 px, painted from noise) for the smooth ground |
| `sfx.gd` | Procedural sound effects |
| `updater.gd` | `G.updater`: when a server runs another version (NetClient sees it in the login challenge), an exported Windows game downloads `DeadBlocks-<v>-windows.zip` from the GitHub release `v<v>`, writes the exe as `DeadBlocks-update.exe` next to itself, and starts it headless with `--finish-update=OLD`. That helper waits for the old game to close, copies itself over it and starts it with `--after-update`; the game then rejoins from `user://update/rejoin.cfg` (`G.autojoin`). Tests: `--update-url`, `--update-target`, `--update-dry-run`, `--finish-no-launch` |
| `autotest.gd` | Automated playtest, run with `-- --autotest`: built on `tests/nettest.gd`, presses Play solo (world "autotest") and plays through the real client against the local server, then quits and continues |
| `bench.gd` | Server load benchmark (Blood Moon horde, explorers streaming chunks), run with `-- --bench` |
| `net/protocol.gd` | `class_name Proto`: message ids and binary layouts, login hashing (HMAC proofs of password and PIN), name/PIN rules, terrain hash. Bump `PROTOCOL` when a layout changes |
| `net/net_server.gd` | Dedicated server networking: ENet listen, login checks and refusals, one ServerPlayer per player, 15 Hz snapshots, clock messages, chat and admin commands (`/dusk /bloodmoon /time /kick /give /spawn /clear /players`; `/kill` for anyone; `/hash` for tests), movement sanity check with corrections, `--hosted-by` stop for Host game and Play solo, `--solo` (the world stops while every player has paused) and `--bind=IP`. Saving through `saver` (autosave, a leaving player's file, everything when the server empties, control-folder commands, `stop_server` = the only clean stop). Owns blocks, inventories, health and food: checks break/place/craft/eat/swap/attack requests (refusal reasons are logged when a player leaves), runs hunger and healing (`_tick_players`), backpacks (M2: `_drop_backpack` on death, `_take_backpack` when one is mined, `_tick_backpacks` lets them fall apart, `S_BACKPACKS` to their owner, saved in world.json), beds and respawning (`beds` index checked against every block change, `_bed_spot`, `_random_spot` within `respawn_radius`, `S_BED`), characters left behind when a player's connection is lost (`lingering`, `_may_linger`, `_end_linger`; they stay in snapshots with `F_AWAY` and in the Sim), and once a tick (`_flush_world`) updates chunk subscriptions, sends edited chunks, edit batches, crack stages and inventories; mob updates (`mob_packets`) go out with the player snapshots |
| `net/net_client.gd` | Client networking (`G.net`): connect + login, welcome → `G.start_client_session`, other players' snapshot history and interpolation (100 ms behind), 15 Hz movement up, chat. After a dropped connection it logs back in by itself for 60 s (`reconnecting`); the same world continues via `G.resume_client_session`. Sends block/inventory requests, keeps the server's inventory plus unacknowledged guesses, and feeds world messages to the world (queued until `attach`) |
| `net/remote_player.gd` | Another player's blocky figure with a name tag (with "(away)" for a character left behind), flashlight, the item in their hand (from the snapshot) and a swinging arm while they mine or hit |
| `server/server_player.gd` | The server's record of a connected player (Sim player record once it is ready): health, food, kills, inventory, subscriptions; zombies hit it through `take_damage` |
| `server/save.gd` | Node `Save`: the server's save files under the data folder (`--data`, default `user://server`): `worlds/<world>/` world.json (with the backpacks; `FORMAT` 2 since M2), players/, chunks/, world.lock, damaged/; backups/ (zips, pruned); control/ (`*.cmd`: stop, save, backup, kick, reset-pin, say); status.json. Crash-safe writes (.tmp, `sync`, rename), SHA-256 on every file, damaged files moved aside, newer formats and other terrain refused. | `server/virtual_player.gd` | Stand-in player for tests and benchmarks (zombies can target it; damage is only counted) |
| `tests/regiontest.gd` | `-- --regiontest`: two besieged groups of every zombie type; prints a hash that must not depend on region order |
| `tests/typetest.gd` | `-- --typetest --server-mode`: each zombie type in an arena built in the air (a crawler through a 1-high tunnel, a runner's 20 m, a brute's blows on planks, a screamer's call, a spitter's acid) |

| `tests/lineup.gd` | `-- --lineup --shots=DIR` (real renderer): a picture of every zombie type, night and Blood Moon, side by side |

## Run / test / build
Replace `godot` with the path to the Godot 4.7.2 executable (on Windows, `Godot_v4.7.2-stable_win64_console.exe` shows console output).

- **Play from the editor:** open `project.godot` in Godot and press F5.
- **The test gate — run before every commit:** `GODOT=<path> ./tools/test_all.sh` (about 30 minutes; `--quick` skips the exports, the Pi checks and the benchmark, about 15 minutes; run it detached, not as a 30-minute-limited background job). It runs the autotest, the save test, the region-order test both ways, the zombie-type test, the multiplayer test, the exports, the PC-vs-Pi terrain check (arm64 export under `qemu-aarch64-static`), the multiplayer test against the arm64 server under qemu, the Pi package test, and a short benchmark. A stage fails on a FAIL line, **any `ERROR`/`SCRIPT ERROR` line**, a crash, a timeout or a missing DONE line. Logs: `build/test_logs/`.
- **Automated playtest (headless):**
  `godot --headless --path . -- --autotest --seed=4242`
  It presses Play solo with a new world "autotest" in the game's data folder (the player's own solo world is left alone) on a server started in the background, prints AUTOTEST PASS/FAIL lines and ends with `AUTOTEST DONE fails=N`. Seed 4242 is the reference seed and should give `fails=0`.
- **Screenshots:** add `--shots=<absolute dir>` and run with a real renderer instead of `--headless`.
- **Server benchmark:** `GODOT=<path to godot> ./tools/run_bench.sh` (5 setups, about 22 minutes; `BENCH_SETUPS=m1` runs only the 2 M1 server setups, about 9 minutes; add `--bench-secs=8` for a quick check). It runs `-- --bench` once per setup on seed 4242, with a temporary `override.cfg` choosing the physics engine, tick rate and physics thread; the M1 setups add `--server-mode`. It prints a results block and saves it to `bench_results/summary.txt`. A single run: `godot --headless --path . -- --bench --seed=4242 [--bench-secs=60] [--zombies=120] [--explorers=7] [--radius=6] [--only=horde] [--net-clients=8]` (`--net-clients` also builds the updates a server sends that many players). Don't run two benchmarks or other heavy work at the same time, or the timings are meaningless.
- **Builds:** `GODOT=<path> ./tools/build_release.sh` exports `build/DeadBlocks.exe` (Windows), a zipped copy, `build/server/DeadBlocksServer.{arm64,x86_64}` (dedicated-server exports, which start in server mode), and `build/DeadBlocksServer-linux-arm64.zip` (the Pi package; no version in its name, so `update.sh` can fetch `releases/latest/download/` from GitHub). **Release tags must be `v<VERSION>` with `DeadBlocks-<VERSION>-windows.zip` attached**: players' games fetch exactly that to update themselves (`updater.gd`). Needs the 4.7.2 export templates (Editor → Manage Export Templates → Download). The .pck is embedded, so each result is a single file.
- **Multiplayer test:** `GODOT=<path> ./tools/run_nettest.sh` (about 11 minutes; it freezes the server with SIGSTOP to test reconnecting and `kill -9`s it to test saving; `NETTEST_SOAK_S=60` lengthens the building soak and `NETTEST_HORDE_S=120` the Blood Moon soak, both default 20 s; `NETTEST_CRASHES=N` sets the number of crashes, default 3): a local server plus headless bot clients; prints NETTEST PASS/FAIL lines and `NETTEST ALL DONE fails=N`. Logs: `build/test_logs/nettest/`. Pass a server command prefix to test an exported server instead (see the script header).
- **Dedicated server:** `godot --headless --path . -- --server --password=S --admins=Marcus [--port=24650] [--max-players=8] [--seed=N] [--data=DIR] [--world=NAME] [--autosave=S] [--new-world]`. Settings can also come from `DIR/server.cfg` (`key=value`: port, password, admins, max_players, day_minutes, autosave_s, world, seed, respawn_radius, linger_s, backpack_s; flags win). The world is saved in DIR (default `user://server`) under `worlds/NAME` (default `main`); `--seed` only applies to a new world; `--new-world` backs up the old one and starts over. **Stop it with `echo stop > DIR/control/stop.cmd`** (it saves and quits): Ctrl+C or `kill` end headless Godot at once without saving. Join from the game's title screen (Join server), or `-- --connect=host[:port] --name=N --pin=P --password=S` to skip the menu.
- **Screenshots with Forward+ here:** software Vulkan (`apt install mesa-vulkan-drivers`, lavapipe) under `xvfb-run -a -s "-screen 0 960x540x24"`, with `--resolution 960x540 -- --scenery --gfx=1 --shots=DIR` (about a minute; it is slow, so use small windows). After adding a `class_name` file, run `godot --headless --path . --import` once or the new class isn't found.
- **Screenshots of the menus and an online session:** run under `xvfb-run` with `--rendering-driver opengl3` and `--nettest=screens --shots=<dir>` (title/Join/Host), or `--nettest=b --shots=<dir>` as the second bot next to a server and an `a` bot.
- **Other flags:** `--gfx=0-3` (graphics quality for this run), `--version` (print "Dead Blocks X.Y.Z" and quit; update.sh uses it), `--server-mode` (simulate like the server), `--day-minutes=N` (default 30), `--radius=N` (chunk radius), `--no-spawns` (server: mobs only from `/spawn`, for tests), `--backpack-s=S` (server: backpacks fall apart after S seconds instead of 600, for tests), `--respawn-radius=M` (server: respawning without a bed lands within M m of the center, default 1000; 0 = the world spawn, which the multiplayer tests use), `--linger-s=S` (server: when a player's connection is lost, their character stays S seconds, default 60; 0 = not at all; leaving through the menu always takes it out at once), `--peer-timeout-ms=N` (server, tests: give up on a silent connection after N–2N ms instead of 15–30 s).

## Testing shortcuts in-game
- F6 (`/dusk`) skips to dusk or dawn; F7 (`/bloodmoon`) jumps to the Blood Moon (day 7, 19:57). They are admin commands: in Play solo and Host game you are the admin; on the Pi, the names in `server.cfg`.
- In chat (T), admins also have `/give item [n]`, `/spawn zombie|night|horde|runner|brute|crawler|screamer|spitter|boar [n]` (a type comes in tonight's mood, red-eyed during a Blood Moon), `/time HOUR`, `/clear` (removes every zombie and animal). Anyone can `/kill` (die and respawn; the pause menu's Die and Respawn does the same).

## Rules for server-side code
- **No physics space queries outside `_physics_process`** (raycasts, shape queries, `direct_space_state`). With physics on its own thread they fail; the test gate's ERROR-line check catches it.
- **Zombie code must not depend on processing order.** In `sim_tick`, read the world and the region's start-of-tick spatial hash only; queue block damage with `G.sim.queue_block_damage(...)` instead of calling `world.damage_block`; use the zombie's own `rng`, never `randf()`. The region-order test checks this.
- **Network messages are our own binary layouts in `net/protocol.gd`** (no RPCs or Synchronizers). Any layout change bumps `Proto.PROTOCOL`, and any release bumps `G.VERSION`: the server refuses other versions at login.
- **Online, the server owns blocks and inventories.** Change blocks on the server through `world.set_block` (it records the edit for clients); never change a client's world or inventory except from server messages or as a guess the server will confirm or undo. Drops and break times come from `Rules`, so solo and server agree.
- Server code runs without a HUD, textures, sounds or a local player (`G.hud`, `G.tex`, `G.sfx`, `G.player` are null): guard UI and sound calls (see `game._say` / `game._sound`).
- **Stopping goes through `NetServer.stop_server`** (control file `stop`, the Host game's watchdog): headless Godot dies instantly on SIGTERM/SIGINT without running any GDScript, so nothing can be saved from a signal. Anything new the server must remember goes into `save_world` (and, if it is per player, `_store_account` and `Save.player_json` / `load_players`).
- `ENetMultiplayerPeer.get_peer(id)` prints an ERROR for a peer that has gone; the server keeps its own `_live` set. `OS.is_process_running` only works for this process's own children.

## Design & roadmap
**Read `DESIGN.md` before starting work.** It records the owner's decisions (4–8 player co-op on a Raspberry Pi 5 dedicated server, Blood Moon rules, death/backpack rules, loot, world) and the milestone plan (M0–M5). Keep it up to date when decisions change.

Other notes:
- Mashup features the owner asked for must be **original**: no copyrighted characters, names or assets. The ideas are a Wizard101-like spell-card system, Elden Ring-like boss fights with dodge-roll, and Naruto-like ability moves. These are parked for later.
- Better art. The owner is fine with the pixel style, and could supply sprites or textures later.
