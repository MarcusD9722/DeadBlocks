# Dead Blocks — project notes for Claude Code

A first-person 3D voxel **zombie survival craft** game. The design blends three games:
- **Minecraft**: a block world you can mine and build in, plus crafting.
- **7 Days to Die**: zombies smash through blocks, with a Blood Moon horde every 7th night.
- **ARK**: wildlife to hunt now, with taming and creatures planned.

The owner (Marcus) playtests on Windows and gives feedback. Each round of work should end with a new Windows build he can run.

## Tech
- **Godot 4.7.2 (standard build, not .NET)**, using the **Forward+** renderer (OpenGL fallback; since the graphics overhaul, `docs/V-plan.md`) and **Jolt Physics**. The game runs physics at 60 ticks/s; server mode runs it at 30 (decided in M0, see DESIGN.md).
- Everything is GDScript plus shaders in `shaders/` (sky, smooth terrain, blocks, leaves, plants, tools). **Art files** (since 0.11.0) live in `assets/`: CC0 photo textures from ambientCG combined by `tools/make_textures.py SOURCE_DIR` into texture strips (`assets/textures/*`, imported as Texture2DArrays by their `.import` files), and since 0.12.0 Quaternius' CC0 animated models in `assets/models/` (zombies, survivors for other players, the pig for the boar; `rig.gd`). Credits in `assets/CREDITS.md`. Tools and weapons are 3D models built in code (`tool_models.gd`, since 0.15.0), and their icons are drawn from those models; other item icons, plant pictures and crack overlays are still painted in code (`tex.gd`), and every sound is synthesized at startup (`sfx.gd`). The dedicated-server export presets exclude `assets/*`: server code must never `preload` anything in `assets/` (use `load()` in client-only code).
- `main.tscn` is the only scene. `game.gd` builds every other node in code.
- Indent with tabs and use typed GDScript where possible.

## File map (`scripts/`)
| File | What it does |
|---|---|
| `g.gd` | Autoload `G`. Global refs (game, world, player, hud, sim, tex, sfx), command-line args (plus `server.cfg` on a server, `_load_server_cfg`), `VERSION`, and `server_mode` (`--server-mode`, `--server`, or the dedicated-server export): no render meshes, lights, mob models or sounds, physics at 30 ticks/s. `mode` is solo (the title screen's own world, and the tests that run in-process) / client / server. Holds the client connection (`G.net`, survives the scene reload into the server's world), `host_game` and `play_solo` (both start a background server process and join it; Play solo binds it to 127.0.0.1 with a random port and password, `--solo`; `G.solo` is then true), `world_info` for the title screen, and `start/end_client_session` |
| `game.gd` | Game states (loading/title/playing/menu/chat/paused/dead, plus connecting and server), day-night clock (the look is `gfx.gd`), Blood Moon, zombie and animal spawning (on the server), input bindings. | `gfx.gd` | `G.gfx` (not on a server): WorldEnvironment, sun/moon light, sky shader, fog and post effects, the day–night look (`update_sky`), and every setting in `opt` (saved in `user://settings.cfg`, `set_opt` applies one at once): quality presets Low/Medium/High/Ultra (`PRESETS`: shadows, SSAO, SSIL, volumetric fog, AA, view distance 4–8) or Custom, brightness (a gamma LUT after tonemapping), light in caves (`min_light`, the shaders' floor for sky light), FOV, render scale (FSR 2), V-Sync, frame cap, window mode, show FPS, mouse sensitivity. `--gfx=N` picks a preset for one run |

| `controls.gd` | `class_name Controls` (M4.1): every input action (`ACTIONS`: move, jump, sprint, attack, use, interact, inventory, map (M4.4), flashlight, chat; plus look_*, hotbar_prev/next, pause), its key or mouse button (rebindable, saved in `user://controls.cfg`, mouse buttons stored as negative numbers), extra fixed keys (arrows, Enter, Esc), and the fixed controller layout (`PAD`, Xbox names; A/B also press and cancel in menus). `pad_in_use` (prompts show controller buttons). | `map_panel.gd` | The Map tab (M4.4): draws MapData's regions, a grid and scale bar, and markers (you, bed, bags, allies and tribe from the snapshots, pins); drag and wheel, right-click adds or removes a pin (a name box); controller: left stick, triggers zoom, A/X pins, right stick centers |
| `smooth_mesher.gd` | `class_name SmoothMesher`: the rounded natural ground (surface nets over the chunk and 4 blocks of its 8 neighbours; corners cut ≤ 0.45, hollows filled ≤ 0.2, smoothed twice; a vertex touching a built block stays on the block corner so the ground meets cubes without a gap; drawn double-sided so a folded triangle never leaves a hole), material weights and sky light per vertex (`sky_at` for cube faces too). **Picture only**: collision stays whole blocks on client and server |
| `tool_models.gd` | `class_name ToolModels` (M4.3, client only): every tool, weapon and ammo as a rounded 3D model built from smooth shapes (`_rod`, `_tube`, `_loft` of sections, `_blob`; one builder per shape) with `shaders/tool.gdshader` materials (`MATS`: wood and stone from the texture arrays Tex hands over, `block_tex`/`terrain_tex`; metals plain; `TIER_MAT` by tier). `make(id, held)` (held: drawn in front of the world), `make_flying` (pointing -Z), `set_draw` (the bow's string and nocked arrow), `set_loaded` (the crossbow), `render_icons` (all icons in one SubViewport frame at startup, into `icons`). Model conventions are at the top of the file |
| `projectile.gd` | An arrow, bolt or thrown spear (M4.3): moved by the Sim (`step`: the first mob on its path via segment tests, `_mob_hit`, twice the damage in the head; else the first solid block, `_block_hit`, where a spear and 3 in 5 arrows stay: `NetServer.add_ground`). Clients see it as `Proto.MOB_PROJ` turned along its motion; the shooter's own copy (`local`) flies by itself |
| `round_box.gd` | `class_name RoundBox`: rounded box meshes for the box models (used when a downloaded model is missing) and the boar's tusks (cached by size) |
| `rig.gd` | `class_name Rig` (client only): a downloaded animated model from `assets/models` (`Rig.make` → null if it can't load, then the caller builds its box model). Animations advanced by hand (`tick`: every frame within 20 m, less often farther away, off screen or headless), `move` (looping idle/walk/run at a rate) and `play_once` (attack, scream, death); own materials per copy (hit flash), `recolor` and `glow` paint palette cells of the texture (zombie skins, eyes), `attach` gives a node following a bone in the model's own coordinates (from the skin's bind pose), `glow_spots` puts glowing eyeballs there, `strip_props` hides the survivors' weapons |
| `world.gd` | Chunked voxel world (16×64×16 chunks). Keeps chunks loaded around one or more centers (`update_centers`, one per player). Terrain generation and meshing run on WorkerThreadPool. A drawn chunk is meshed once all 8 neighbours have data (SmoothMesher), as up to four surfaces (smooth ground; cubes, boxes and round log trunks with the block array; leaves as leafy faces just outside the block plus two planes through it, swaying; plants with the pixel atlas); its collision is `_build_collision` (whole blocks, as on the server, which still needs only the 4 side neighbours); an edit within 4 blocks of a border remeshes the neighbours; finished meshes go into the world within 3 ms per frame (`_drain_done`), and a headless game skips the drawn-ground body. A client's world notes changed chunks for the map (`track_map`, `map_dirty`). Drawn chunks also get a second, collision-free body on `VISUAL_LAYER` (the rounded ground and solid cubes as drawn), only for measuring where creatures should stand (game.gd `_ground_offset`). Also holds raycasts, set_block (`set_block(p, id, meta)`: block states, M4.2, kept sparse per chunk in `Chunk.meta`, `block_meta`; `clear_block` takes a door's other half too, `door_partner`), zombie block damage with crack overlays (`damage_of`, `repair_block` for the hammer; `destroyed` lists blocks zombies broke, for boxes), the torch/campfire lights, the box-shaped blocks and the M4.2 shapes (half blocks, pillars, doors, hatches as `MeshBuf.box` per `Blocks.boxes_of`; ramps as `MeshBuf.ramp`, colliding as two steps) and the beacon beam over each backpack. Server: `record_edits` collects every block change for NetServer. Client online (`remote`): only chunks the server subscribed as fresh are generated; edited ones arrive as copies (`net_subscribe/net_chunk/net_edits`) |
| `world_gen.gd` | Deterministic terrain: hills, plains/forest/desert biomes, caves, coal/iron ore, trees, berry bushes |
| `blocks.gd` | Block ids and per-block tables (atlas tiles, shape, solid, opaque, full, hardness, tool, required pick tier, zombie HP), built when the class loads (`_static_init`) from `_BASE` plus the M4.2 structure tiers (`TIER_BLOCKS`: Wood Frame, Planks, Reinforced Wood, Iron, Steel, Blood-forged; each also as `FRAME_HALF/FRAME_RAMP/FRAME_PILLAR + tier`), doors and hatches (closed and open are separate ids, `OPENS`/`CLOSED`, so solidity follows from the id) and storage boxes (`BOX_SLOTS`). Block states (`META_FACING` bits 0–1, `META_UPPER`); `boxes_of(id, meta)` is a shape's boxes for picture and collision; `UPGRADE` and `REPAIR` are the hammer's tables. **Block id = item id** (`item_of`: an open door drops the closed one). `BACKPACK` is a block that never goes into an inventory. `STATIONS` maps the crafting stations (workbench, forge, campfire, Blood Forge) to their recipe names. Block ids are bytes everywhere (chunks, edits, requests; 61 of 256 used) |
| `items.gd` | Non-block items (ids ≥ 100): tools (pickaxe, axe, shovel in tiers 1–5: wood, stone, iron, steel, Blood Steel; `TIER_MULT`, `TIER_NAMES`), weapons, ingots, Blood Shards, food; hammers (M4.2: Wooden Mallet to Blood Steel, `hammer_time`); M4.3 spears (`throw` damage), bow, crossbow (`ammo`), arrows and bolts (`ammo_of`), `PROJECTILES` (a projectile's type on the network), `ammo_slot` (which ammo is shot next; client and server alike), `reach`, draw/reload/charge times |

## Run / test / build
Replace `godot` with the path to the Godot 4.7.2 executable (on Windows, `Godot_v4.7.2-stable_win64_console.exe` shows console output).

- **Play from the editor:** open `project.godot` in Godot and press F5.
- **The test gate — Marcus runs it** (decided after 0.14.0: it takes too long in Claude's cloud sessions). Claude does not run the full gate; before committing, Claude runs the tests that cover what changed (usually the autotest, plus the save, mesh, region, zombie-type or multiplayer test for those parts) and says which ran. The gate: `GODOT=<path> ./tools/test_all.sh` (about 30 minutes; `--quick` skips the exports, the Pi checks and the benchmark, about 15 minutes; run it detached, not as a 30-minute-limited background job). It runs the autotest, the save test, the mesh test (no holes in the drawn world), the region-order test both ways, the zombie-type test, the multiplayer test, the exports, the PC-vs-Pi terrain check (arm64 export under `qemu-aarch64-static`), the multiplayer test against the arm64 server under qemu, the Pi package test, and a short benchmark. A stage fails on a FAIL line, **any `ERROR`/`SCRIPT ERROR` line**, a crash, a timeout or a missing DONE line. Logs: `build/test_logs/`.
- **Automated playtest (headless):**
  `godot --headless --path . -- --autotest --seed=4242`
  It presses Play solo with a new world "autotest" in the game's data folder (the player's own solo world is left alone) on a server started in the background, prints AUTOTEST PASS/FAIL lines and ends with `AUTOTEST DONE fails=N`. Seed 4242 is the reference seed and should give `fails=0`.
- **Screenshots:** add `--shots=<absolute dir>` and run with a real renderer instead of `--headless`.
- **Server benchmark:** `GODOT=<path to godot> ./tools/run_bench.sh` (5 setups, about 22 minutes; `BENCH_SETUPS=m1` runs only the 2 M1 server setups, about 9 minutes; add `--bench-secs=8` for a quick check). It runs `-- --bench` once per setup on seed 4242, with a temporary `override.cfg` choosing the physics engine, tick rate and physics thread; the M1 setups add `--server-mode`. It prints a results block and saves it to `bench_results/summary.txt`. A single run: `godot --headless --path . -- --bench --seed=4242 [--bench-secs=60] [--zombies=120] [--explorers=7] [--radius=6] [--only=horde] [--net-clients=8]` (`--net-clients` also builds the updates a server sends that many players). Don't run two benchmarks or other heavy work at the same time, or the timings are meaningless.
- **Builds:** `GODOT=<path> ./tools/build_release.sh` exports `build/DeadBlocks.exe` (Windows), a zipped copy, `build/server/DeadBlocksServer.{arm64,x86_64}` (dedicated-server exports, which start in server mode), and `build/DeadBlocksServer-linux-arm64.zip` (the Pi package; no version in its name, so `update.sh` can fetch `releases/latest/download/` from GitHub). **Release tags must be `v<VERSION>` with `DeadBlocks-<VERSION>-windows.zip` attached**: players' games fetch exactly that to update themselves (`updater.gd`). Needs the 4.7.2 export templates (Editor → Manage Export Templates → Download). The .pck is embedded, so each result is a single file.
- **Multiplayer test:** `GODOT=<path> ./tools/run_nettest.sh` (about 11 minutes; it freezes the server with SIGSTOP to test reconnecting and `kill -9`s it to test saving; `NETTEST_SOAK_S=60` lengthens the building soak and `NETTEST_HORDE_S=120` the Blood Moon soak, both default 20 s; `NETTEST_CRASHES=N` sets the number of crashes, default 3): a local server plus headless bot clients; prints NETTEST PASS/FAIL lines and `NETTEST ALL DONE fails=N`. Logs: `build/test_logs/nettest/`. Pass a server command prefix to test an exported server instead (see the script header).
- **Dedicated server:** `godot --headless --path . -- --server --password=S --admins=Marcus [--port=24650] [--max-players=8] [--seed=N] [--data=DIR] [--world=NAME] [--autosave=S] [--new-world]`. Settings can also come from `DIR/server.cfg` (`key=value`: port, password, admins, max_players, day_minutes, autosave_s, world, seed, respawn_radius, linger_s, backpack_s; flags win). The world is saved in DIR (default `user://server`) under `worlds/NAME` (default `main`); `--seed` only applies to a new world; `--new-world` backs up the old one and starts over. **Stop it with `echo stop > DIR/control/stop.cmd`** (it saves and quits): Ctrl+C or `kill` end headless Godot at once without saving. Join from the game's title screen (Join server), or `-- --connect=host[:port] --name=N --pin=P --password=S` to skip the menu.
- **Screenshots with Forward+ here:** software Vulkan (`apt install mesa-vulkan-drivers`, lavapipe) under `xvfb-run -a -s "-screen 0 960x540x24"`, with `--resolution 960x540 -- --scenery --gfx=1 --shots=DIR` (about a minute; it is slow, so use small windows). After adding a `class_name` file, run `godot --headless --path . --import` once or the new class isn't found.
- **Screenshots of the menus and an online session:** run under `xvfb-run` with `--rendering-driver opengl3` and `--nettest=screens --shots=<dir>` (title/Join/Host), or `--nettest=b --shots=<dir>` as the second bot next to a server and an `a` bot.
- **Other flags:** `--gfx=0-3` (graphics quality for this run), `--version` (print "Dead Blocks X.Y.Z" and quit; update.sh uses it), `--server-mode` (simulate like the server), `--day-minutes=N` (default 30), `--radius=N` (chunk radius), `--no-spawns` (server: mobs only from `/spawn`, for tests), `--backpack-s=S` (server: backpacks fall apart after S seconds instead of 600, for tests), `--respawn-radius=M` (server: respawning without a bed lands within M m of the center, default 1000; 0 = the world spawn, which the multiplayer tests use), `--linger-s=S` (server: when a player's connection is lost, their character stays S seconds, default 60; 0 = not at all; leaving through the menu always takes it out at once), `--peer-timeout-ms=N` (server, tests: give up on a silent connection after N–2N ms instead of 15–30 s).

## Controls (M4.1)
- **E** interacts (opens the workbench, forge, campfire or Blood Forge you look at; opens and closes doors and hatches; opens a storage box or bag); **I** opens your inventory with hand crafting. Both close their screen again, as does Esc. Right-click only places, eats and uses. Holding the mine button with a hammer upgrades or repairs the block (M4.2). M4.3: hold the mine button to draw the bow and let go to shoot; click to shoot the crossbow (it reloads itself); a spear stabs with the mine button, or hold right-click and let go to throw it; E picks up a spear or arrow lying in the world.
- M4.4: **I** opens the character screen on its Inventory tab, **M** (the controller's Back) on the Map tab; the tabs (Inventory, Map, Players, Tribe) switch by clicking or with LB / RB, and I or M again closes it. `/t message` is the tribe chat.
- Keys can be changed in Settings; the controller layout is fixed (`controls.gd` `PAD`). New UI must be focusable (`focus_mode` not NONE) and give a control the focus when it opens (`hud.focus_first`), so a controller can use it.

## Testing shortcuts in-game
- F6 (`/dusk`) skips to dusk or dawn; F7 (`/bloodmoon`) jumps to the Blood Moon (day 7, 19:57). They are admin commands: in Play solo and Host game you are the admin; on the Pi, the names in `server.cfg`.

## Rules for server-side code
- **No physics space queries outside `_physics_process`** (raycasts, shape queries, `direct_space_state`). With physics on its own thread they fail; the test gate's ERROR-line check catches it.
- **Zombie code must not depend on processing order.** In `sim_tick`, read the world and the region's start-of-tick spatial hash only; queue block damage with `G.sim.queue_block_damage(...)` instead of calling `world.damage_block`; use the zombie's own `rng`, never `randf()`. The region-order test checks this.
- **Network messages are our own binary layouts in `net/protocol.gd`** (no RPCs or Synchronizers). Any layout change bumps `Proto.PROTOCOL`, and any release bumps `G.VERSION`: the server refuses other versions at login.
- **Online, the server owns blocks and inventories.** Change blocks on the server through `world.set_block` (it records the edit for clients); never change a client's world or inventory except from server messages or as a guess the server will confirm or undo. Drops and break times come from `Rules`, so solo and server agree.
- Server code runs without a HUD, textures, sounds or a local player (`G.hud`, `G.tex`, `G.sfx`, `G.player` are null): guard UI and sound calls (see `game._say` / `game._sound`).
- **Stopping goes through `NetServer.stop_server`** (control file `stop`, the Host game's watchdog): headless Godot dies instantly on SIGTERM/SIGINT without running any GDScript, so nothing can be saved from a signal. Anything new the server must remember goes into `save_world` (and, if it is per player, `_store_account` and `Save.player_json` / `load_players`).
- `ENetMultiplayerPeer.get_peer(id)` prints an ERROR for a peer that has gone; the server keeps its own `_live` set. `OS.is_process_running` only works for this process's own children.
